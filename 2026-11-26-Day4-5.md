## Communication Protocols

Believe it or not all forms of communication have predetermined rules to govern the convo:
- What method of communication should we use?
- What language should we use?
- Do we need to confirm that our messages are received?

Basically conversations need a agreed upon methods and or medium to actually carry out a successful convo.

Computers need this to communicate with eachother, just with a different tpe of proctol:

- Message Format: Does the message need a specific format or channel to be in in order to be sent
- Message size: Messages may need to be a specific length due to memory issues or readability
- Timing: How fast the message is trasmitted
- Encoding: How the message is converted in order to be sent (what media does it take) EX: converting into light or eletric pulses
- Encapsulation: Formatting and grouping the message with other data like recieve info and destination
- Message Pattern: A message may need an acknowledgment to be sent.

Network and Internet Standards allow how all versions of techologies to be able communicate and coexist with each other.

When a new standard is proposed, it goes through a process that is recorded in a Request for Comments (RFC) document. RFCS are published and managed by the Internet Engineering Task Force (IETF).

- Ethernet Protocol: Guides NICS towards eachother within the same Network
- IP: Governs commincation from origin to Destination
- TCP: Makes sure the message comes in reliably and in order. 
- http: Governs the transfer of HTML

Protocol stacks:
Many times a task needs multiple protocols to carry out
Protocols are stacked and used at once during tasks.

Layered Models help visualize how protocols work together during a task get achieve its proper result.

The layered Model can:
- assist protcol design as protocols may use or send data or information to layers above and below itself
- Fosters competition cause products can be compatible with eachother
- Changes can be local to its own level
- Standardizes common langues to describe network functions and capabilities 

- Application: Represents data to the user, along with encoding and dialog control
- Transport: Supports Communication between devices on a network
- Internet: Determines cheapest or best path through a network
- Network Access: determines the hardware and media that make up a network

OSI reference model

Protocol Model: a conceptual framework that standardizes how data is sent and received between different devices on a network

Reference Model: A conceptual blueprint that describes what functions must be completed at each layer, but does not dictate how to build them.

OSI LAYER:

- Application: Proccess to Process Communication
- Presentation: Representation of data transferred between application layer services
- Session: Organizes and manages data in the presentiation layer
- Transport: To segment, Transfer and reassemble data from communication between end devices
- Network: Provides services to exchange data between end devices
- Data Link: describes the methods to share data between devices over a common media
- Physical: Describes the real mechanical and eletrical proccesses carrying on to transmit data over a network.

TCP/IP model is best used to visualize the interactions of various protocols that make up the protocol suite.

TCP/IP can be described in terms that would fit the OSI model.

## 6.1 Network media Types

Modern Networks usually use 1 of three medias to tasnfer data

- Metal Wires: Eletrical Pulses
- Glass or plastic fiber optic wires: light pulses
- Wireless: Radio or electromagnetic frequencies 

The four aspects taken into consideration when choosing media are as follows:

- Whats the maximum range needed that the network needs to cover
- where will the network be installed
- what bandwidth/speed is needed
- whats the cost of the media and installation fees.

Common network cable:
- Twisted Pairs: Usually used in ethernet, 4 groups of color coded paired wires twisted together to reduce interference 
- Coaxial: Old type of wire, one long strand of copper wire that transmits eletric pulses. Usually covere by protective insulation. usually used for Cable tv to carry highr equency or high broadband signals.
- Fiber Optic: Powerful and expensive media to use, usually used for big data centeres that ar every data intensive. Uses plastic or glass wiring to transmit light signals are a very high speed. Since its not eletrical based, there is no worry for electrical interference.

# Mod 7 The Access Layer

## 7.1 Encasulation and the ethernet Frame

Ethernet Frame:

- Preamble (7 bytes): Syncing the NIC with the bits coming through the media

- Start Frame Delimiter (1 byte): Indicates to the NIC when the actual information reguarding the ethernet frame is coming

- Desination MAC address(6 bytes): the MAC address of the destination NIC

- Source MAC address (6 bytes): the MAC address the the device that the ethernet frame originates from

- Length/type (2 bytes): Either the length(in bytes) of the data(payload) or what kinda of data is coming (is it a ipv4 or ipv6)

- Data (46-1500 bytes): the data that is being encasulated

- Frame Check Sequence (4 bytes): Used by the reciever in order to check vailidity of the data that is recieved. 

Encapsulation: The proccess of formatting and organizing data into the format of the Ethernet frame. (like formatting a envelope to be properly shipped to the correct address)

Encapsulation takes place in the data link layer (layer 2) of the OSI model

## 7.2 The access layer

Ethernet Switches: Operate at layer 2. They allow a single router port to 
split into multiple wired connections to connect multiple devices at once

MAC Address Table:
A table of Port-Address pairs.
When looking at a source address, it looks if the address is already indexed in the MAC address table, if not, index it into the table.

If a destination MAC Address is NOT found in a table (unknown unicast) it will sent out the ethernet frame to every port in the switch (besides the port that sent the frame). Each port will compare its own mac address to the frame that it sent in order to find a match, thus finding where the destination port-address pair is.



The switch considered the MAC addresses found the ethernet frame sent by a device in order to know where to direct that ethernet frame. The Switch looks in its MAC Address take to locate where a device is based on which port that MAC address is connected to.
